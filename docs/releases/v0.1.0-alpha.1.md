# Farol 0.1.0-alpha.1

The first alpha of Farol, an open-source MCP server that gives AI coding agents compiler-accurate understanding of C#
and VB.NET solutions, from classic .NET Framework projects to .NET 10.

## Install

- **Claude Code:** run `/plugin marketplace add yuriafp/Farol`, then `/plugin install farol@farol`. You get the server,
  a hook that checks every `.cs`/`.vb` edit, a modernization skill and four prompts.
- **Any MCP client:** `dotnet dnx Farol.Mcp@0.1.0-alpha.1 --yes`, which needs the .NET 10 SDK. Classic .NET Framework
  projects also need Windows with Visual Studio's MSBuild.

Setup for each client: [README](https://github.com/yuriafp/Farol#install).

## What's in it

18 tools:

- **Workspace:** `dotnet_workspace`, `dotnet_overview`.
- **Navigation, in C# and VB:** `dotnet_find_symbols`, `dotnet_symbol`, `dotnet_find_references`, `dotnet_hierarchy`,
  `dotnet_call_hierarchy`, `dotnet_outline`. `dotnet_find_references` also returns markup references (WebForms,
  ASMX/WCF/handlers, XAML) and the uses through the interface members a member implements.
- **Verification:** `dotnet_check` reports only the diagnostics your edits introduced. `dotnet_code_actions` returns
  Roslyn's fixes and refactorings as diffs.
- **Build and test:** `dotnet_build`, and `dotnet_test`, which can run only the tests your edits reach.
- **Packages:** `dotnet_packages` lists vulnerable, deprecated and outdated packages, `packages.config` included.
  `dotnet_package_api` returns the API of an exact package version.
- **Legacy modernization:** `dotnet_legacy_inventory`, `dotnet_portability`, `dotnet_config_inspect`,
  `dotnet_migration_plan`.

It also ships four prompts: `explore`, `verify_changes`, `upgrade_package` and `modernize`. The `--read-only` option
refuses to write files, build or run tests.

## Measured

**Speed:** measured in CI on 4 cores, after the background warm-up, on two large solutions:

- Umbraco CMS 18.2.0, 0.77M lines;
- DNN Platform 10.3.3, 0.58M lines of C# and VB on .NET Framework.

| Measure | p95 on both solutions | Target |
|---|---:|---:|
| Symbol queries | 43 ms or less | 100 ms |
| `dotnet_find_references` | 579 ms or less | 1 s |
| `dotnet_check` after an edit | 1.34 s or less | 2 s |

Peak memory stayed at or under 1.33 GB.

**Evals:** with Claude Haiku 4.5 on 30 tasks that grep + build often fails, Farol succeeded in 59% of runs against 28%
without it, using 32% fewer tokens
([results](https://github.com/yuriafp/Farol/blob/main/evals/results/2026-10-07-haiku.md)). With Sonnet 5.5, grep +
build had already solved every task of the first set
([results](https://github.com/yuriafp/Farol/blob/main/evals/results/2026-10-05.md)).

## Known limits

- Validated on Windows with Visual Studio 2026. The VS Code setup is documented but not validated.
- `dotnet_build` and `dotnet_test` run synchronously and report progress notifications, because the C# MCP SDK does not
  implement tasks yet.
- `dotnet_check` reports compiler diagnostics only. Analyzer rules come with `dotnet_build`.

Scope and acceptance criteria: [spec 001](https://github.com/yuriafp/Farol/blob/main/docs/specs/001-mvp.md).
